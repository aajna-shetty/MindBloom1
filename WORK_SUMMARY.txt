1. Project purpose
------------------

MindBloom is a work-in-progress FastAPI application for experimental,
early autism-risk screening. It combines:

- Questionnaire-based machine learning.
- Optional video-based behavioral feature extraction.
- Hybrid risk scoring.
- Child profiles and screening-result persistence through SQLAlchemy.

This is a screening aid, not a diagnostic tool. It still requires clinical
validation, privacy/security controls, usability work, and production
hardening before real-world use.

3. Existing API capabilities
----------------------------

- GET /health
  Checks whether the questionnaire model is loaded.
- GET /questions
  Returns the questionnaire and question count to authenticated caregivers.
- POST /profiles/
  Creates a child profile.
- POST /predict
  Calculates a questionnaire score and hybrid risk result, then stores the
  screening transaction.
- POST /video/analyze
  Runs the webcam or video-file pipeline for an existing child profile and
  returns video-analysis information.
- POST /video/analyze/upload
  Accepts a validated temporary upload, runs the same protected analysis
  pipeline, and removes the temporary file afterward.


4. Video pipeline
-----------------

The current processing flow is:

Video source
  -> OpenCV frame capture
  -> MediaPipe face landmarks
  -> geometric behavioral features
  -> sampled DeepFace emotion probabilities
  -> session time-series aggregation
  -> 47-feature vector
  -> video model risk estimate
  -> questionnaire/video fusion

Responsibilities are separated as follows:

- OpenCV captures frames.
- MediaPipe detects landmarks and derives geometry.
- DeepFace provides expression/affect estimates.
- The Random Forest is the classification component.

No individual computer-vision signal is directly treated as an autism
classification decision.


5. Model and data status
------------------------

- Existing questionnaire model artifacts are present under models/.
- The MediaPipe face-landmarker.task asset is included.
- The three CSV files under data/ are questionnaire/demographic datasets.
- A trained video_model.pkl is not currently available.
- The existing CSV files cannot be used as video-feature training data.
- train_video.py is available, but real labeled video-derived feature data is
  required before a video model can be trained.
- Until a video model is trained and available, video analysis reports that
  the video model is unavailable rather than producing a video prediction.


6. Testing and development support
----------------------------------

The repository includes:

- Core video unit tests under tests/video/.
- DeepFace and emotion visual tests.
- Camera and MediaPipe checks.
- Startup timing checks.
- Model-artifact auditing.
- A development harness at app/video/test.py.

The development harness can be run with:

    python -m app.video.test

The complete test suite can be run with:

    pytest

Some tests need a working camera, model assets, or compatible computer-vision
runtime dependencies.


7. Setup and run commands
-------------------------

Create and activate a virtual environment:

    python -m venv .venv
    .\.venv\Scripts\Activate.ps1

Install dependencies:

    python -m pip install --upgrade pip
    pip install -r requirements.txt

Start the API:

    uvicorn app.main:app --reload

Open API documentation:

    http://127.0.0.1:8000/docs

Train the existing questionnaire model:

    python train.py

Train the video model after obtaining suitable labeled video-derived data:

    python train_video.py
